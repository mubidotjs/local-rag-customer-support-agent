# Milestone 3 — offline document lifecycle

Baseline: `4d10e3b59a55dce71a5252f78939882f75b0ad20`. **Real-model status: NOT RERUN.** Zero actual embedding, generation, model metadata, download or live browser-to-model requests. Historical Phase D authorization remains consumed.

## Delivered behavior

CLI-only preview/apply operations support explicit document add, update, delete and reindex, plus status/version inspection and explicit SQLite recovery. Every apply requires the exact preview confirmation token. A missing source file never causes deletion. Reindex reads stored sources; it does not synchronize a directory. The original directory ingestion command remains compatible and immutable for changed populated corpora.

The existing schema supports lifecycle metadata without a table migration. New managed indexes bind vectors to a model digest and preprocessing fingerprint. Legacy indexes remain readable but require an explicitly confirmed full reindex with zero vector reuse before incremental additions/updates. Unchanged vectors are reused byte-for-byte, including per-chunk duplicate-vector distinctions; changed boundaries recompute ordinal IDs and offsets. No cross-model, cross-configuration or approximate-content reuse is permitted.

Writes use `BEGIN IMMEDIATE`, stale-source/index checks before and after embedding preparation, final source/vector/FTS5/foreign-key/page-budget validation and one commit. Exceptions, lock timeouts and commit failures roll back. Read-only answering holds a consistent transaction snapshot. DELETE journal mode is required for lifecycle; WAL is rejected. Explicit recovery delegates hot-journal rollback to SQLite and then verifies the recovered index without row repair or re-embedding.

## Remaining limitations and future acceptance

This milestone establishes deterministic storage/reuse/recovery contracts, not live-model acceptance. Stable document IDs do not imply immutable ordinal chunk IDs after shifted boundaries. There is no undo/version history, source editing, synchronization mode, WAL lifecycle support, multi-user administration or media-corruption repair. A stale operation may discard already prepared embedding work; it never retries automatically. The local owner and daemon remain trusted not to replace databases or retag models maliciously.

A separate small real embedding/reindex acceptance is warranted before using a real managed index. [Proposed ceiling](proposed-live-budget.json): **3 embedding POSTs, 6 metadata GETs, 0 generation/query/browser requests, 10 minutes, one attempt per step, zero retries/downloads/substitutions**, existing pinned nomic digest only, fresh isolated fictional database. Metadata-only update/no-op/deletion require zero requests. This proposal is **not approved or executed**; a future authorized runner must enforce and journal those ceilings. No new live budget is exercised by this task.
